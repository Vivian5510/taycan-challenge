# 多个调用共用一次同步的返回边界

32个同步调用者可以同时把请求提交给RocksDB的WriteThread。leader合并当前队列里的兼容请求，
把它们的WAL记录全部写完，执行一次fsync，成功后再完成这组请求；组内每个调用者都等待同一同步。
此处约16是实验中的平均值，既不是固定阈值，也不是提前确认后每16次才补一次同步。

| 崩溃点 | 请求是否已返回成功 | 允许的恢复结果 |
|---|---|---|
| WAL记录尚未全部写完/同步未完成 | 本组未返回成功 | 未确认尾部可能存在或丢失；此前ACK前缀必须保留 |
| 同步成功，部分线程尚未收到返回 | 部分调用者结果未知 | 完整同步组已持久化；未收到返回也可能恢复为已生效 |
| 调用者已收到成功 | 已确认 | 该操作的状态必须可恢复，考虑之后的合法覆盖/删除 |

这不提供额外跨Key事务承诺。单Key Put/Delete仍使用原API语义。目录同步、WAL轮换、
恢复校验等仍是实现责任，不能只数fsync次数断言全故障模型通过。

上一轮同条件实验已拦截真实内核fsync：暂停时无ACK、EIO无成功ACK、同步后ACK再kill可恢复；
双方相同的未确认页丢失模型也通过。原始证据见
[同步边界](../f2-recovery-sync-audit-20261114/syscall-boundaries/results.json)和
[同一页丢失故障](../f2-recovery-sync-audit-20261114/same-page-loss/results.json)。
