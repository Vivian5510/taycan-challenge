# 下一轮定位依据

本轮性能确认没有有效增益，不能把回调上限从1改2当优化交付。

两个可复查问题应分别处理：

1. 完成回调批量分发在栈上隐藏兄弟事件的可重入性缺陷，已有确定性小组件实验。
   后续实现应在执行任何回调前，使待执行事件仍能被合法重入poll取到；然后验证
   descriptor/buffer生命周期、短读/写错误、节流、GC及恢复。不能仅调小批量规避。
2. 真实Compaction复制结束后，GC等待独占维护门、读者在Pending路径持共享门的停滞。
   Buffered案例第12周期serial400301处长期无文件/事件进展；hot-inline补跑若复现，
   以独立完整结果和栈记录为准。尚未证明与上述组件缺陷同因；尤其poll上限1也可能
   出现这一现象，所以不能把全部问题归因到批量回调。

后续需记录读者cold/index pending请求地址、请求状态、各allocator的
begin/head/read-only/flushed/tail及epoch，确认到底在等哪项推进条件。
先用可控交错实验验证条件，再改维护门/回收顺序；不要通过关闭GC或改变ACK边界提分。
