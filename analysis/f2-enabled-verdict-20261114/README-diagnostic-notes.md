# 本轮监控与调度问题记录

- 第一组监控线程误用不存在的 `abort` 方法，接近2GiB后线程停止，compaction_crash 准备worker继续运行。发现时核对精确PID/命令并终止，原结果保留unexpected_exit:-9，另有external-guard.json记录真实原因。没有进入SIGKILL验收，也没有达到空间断言，不能声称引擎数据失败；失败库原地保留，不复制。
- 其余场景等待器匹配`python3`文本，而macOS实际进程可执行名为`.../Python`，导致sequential/overwrite与第一轮部分性能格子重叠。已停止残留worker，受影响四个格子见contention.json；所有原日志保留，比较汇总排除这些数据。sequential的内容正确性PASS仍成立，其耗时不用于性能。overwrite中止不冒充失败断言。
- 后续测试显式等待性能全部结束再启动；监控改用已有`_fail`接口，并分别统计每个LOCK所在数据库，2GiB单库保护不再混入全部case日志文件。
- 原引擎源码、参数、测试断言未为这些监控修正而改变。后续新结果独立目录，旧失败/中止记录不覆盖。

- 1600万按需加载和2000万内存场景的存活KV原始数据分别至少3.072GB/2.560GB，超过AGENTS单库2GiB限制。前者部分运行后按容量预检停止，后者未启动；没有缩小Key数。原FAIL/NOT_RUN保留。
- 随机500万Key场景触及本地600秒时限，保留FAIL:timeout。栈采样和目录/GC进度显示在推进，不把长时间压缩说成确定死锁；不能用600秒替代官方86400秒裁定超时。
